# Reference analysis protocol

The supplied `references/original_inspiration.zip` contains static PNG inspiration frames; the six JPEGs are the user's earlier UI reference examples. Do not infer original motion from stills. Treat the six JPEGs as anchor examples for: navigation UI with amber depth; black purple calendar with hierarchy; colorful detailed analytics widgets; translucent profile panel; layered payment cards; dark finance chart. These are *visual observations* only.

For every archive item: record filename, dimensions, hash, duplicate group, content category, observed palette, background, UI anatomy, typography hierarchy, border radius, shadows, detail density, focal hierarchy, proposed motion opportunity, and what must NOT be copied. If there are near duplicates, group them and explain the grouping. Make a readable top-level summary of 10–20 strongest references and why they matter.

Create `docs/reference-database.md` with the inventory and `docs/style-decisions.md` separating (a) observed evidence, (b) art-direction inference, (c) decisions for this video. If actual video files are later supplied, sample them at several timestamps and record observable movement separately.

Reference fidelity means reproducing the LEVEL OF POLISH, not cloning exact screens, words, colors or layouts. The user's explicit correction supersedes prior design mockups: the output should be more sophisticated than simple SaaS cards, but still fundamentally UI motion design, not extravagant 3D product animation.
