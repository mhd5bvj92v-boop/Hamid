# Project rules

This repository finishes the user's **already-cut talking-head videos** with Claude Code and Remotion.

- **Remotion-first (non-negotiable).** Every actual edit is implemented and rendered through Remotion: captions and text animation, on-screen UI, half-screen and full-screen compositions, transitions and effects, sound-effect placement and the final audio mix, all layered over the untouched footage in one composition (`StudioEdit` in the Studio, `Edit-<slug>` on the CLI). The final MP4 is that Remotion render (`edit_render.py final` or the Studio's Export). No second rendering system for any animation type. FFmpeg, numpy and the System D scripts are only for inspection, transcoding, planning/analysing the sound (`sound_mix.py` is an offline check of the plan, never the deliverable) and QC (`edit_qc.py` checks the Remotion render). An edit is done only when it is in the Remotion composition and rendered successfully (`edit_decisions.py built` renders it first). Roles: **Claude Code** analyses the transcript and video, reads the skill, suggests concepts, interprets instructions, writes and updates Remotion components, implements approved revisions and validates the results; **Remotion** composes and renders everything; the **Creative Director Studio** plans and selects edits (Scene Planning + Timeline Editor over the same `edit.json`), previews the actual Remotion composition and sends approved instructions to Claude Code as requests.
- For any talking-head editing request (captions, overlays, full-screen scenes, sound design, export), use the **`video-editing`** skill (`.claude/skills/video-editing/SKILL.md`). Its workflow is the default for every project, and its non-negotiables override generic habits and other skills.
- **The user is the Creative Director of every video.** Follow the five phases in `.claude/skills/video-editing/references/creative-director.md`: analyze, then three library-grounded concepts A/B/C plus D (their own idea) per major moment, presented directly in chat or chosen by the user in the Creative Director Studio (`remotion-app`, `npm run studio`: our editor around the Remotion Player; Remotion itself has no questionnaire), then a grouped storyboard and their approval of the direction, then motion previews with draft sound and feedback, and the final full-resolution render only after their explicit final approval. Everything is recorded in the single project file `remotion-app/src/projects/<slug>/edit.json` (via `edit_decisions.py` or the Studio), which the Player, previews and final renderer all read; never record an approval they didn't give. Run `python3 .claude/skills/video-editing/scripts/edit_decisions.py pending` to see requests the user left for Claude Code in the Studio (concepts, builds from approved scene plans or choices, revisions), `show` to read one, and finish them with `propose` / `built`.
- **The user's timestamped script is the timing source.** Import it as written (`remotion-app/scripts/import-transcript.ts` or the Studio). Never rewrite their words or change their timestamps; flag missing or invalid times for them to fix. Automatic transcription is optional and not installed; don't spend time installing speech recognition unless they ask.
- Never cut, trim, re-order, speed-change or re-voice the user's footage, and never shorten or lengthen pauses. The original file is never modified; full-screen scenes cover the footage while its timeline keeps running. Prove it with `edit_qc.py` before delivering.
- The `remotion-best-practices` skill provides Remotion API knowledge only. Where it suggests something else (for example opening Studio instead of rendering, or cloud rendering), the `video-editing` workflow wins. Render locally; never deploy to AWS/Lambda or add paid render services.
- Rendered media and footage never go into git (`work/`, `remotion-app/out/`, `remotion-app/public/projects/` are ignored). Commit source only.
- Only use sound effects the user has authorised and that are actually indexed and accessible. Never claim a sound was added if it wasn't.
- **3D and realistic objects (hands, people, products, devices, planets...) come from the user, never from code shapes.** A concept that needs one asks for it under `assets` (what + format spec); the user uploads it in the Studio or gives a path (`edit_decisions.py asset`), and `built` refuses until it is provided and used. Stage it with the kit kind `AssetScene` or `<AssetMedia>` (`src/kit/Asset.tsx`). Code builds type, UI, charts, light and particles.
- **Every build must hold up next to its style reference** (SKILL.md rule 12): build with `src/kit/premium.tsx` and `references/premium-motion.md`, run `edit_decisions.py preview`, open the comparison sheet and iterate; `built` needs the previewed beat and a `match` list.
- **Every scene follows the edit's style** (constants): the 60-30-10 palette via `usePalette()`, a camera move via `<CameraMove>`, and the safe area for framing (`src/kit/style.tsx`, `premium-motion.md` §3b). `preview` measures palette and motion.
- **Libraries first:** text animations (`KineticText`, 12 styles), backgrounds (`Backdrop`, 12 presets + `backgrounds/custom.tsx`), camera moves (zoom in/out slow/fast, peak-middle, drift, orbit) and the user's own reference library (`library/references.json`); see `premium-motion.md` §2b. Every component uses `useCanvas()` so it works in 9:16, 16:9 and 4K.
- Studio changes must keep `npm run studio:test`, `npm run studio:test:claude`, `npm run studio:test:plan`, `npm run studio:test:assets` (end-to-end in Chromium) and `npm run lint` passing.
- Remotion's own browser download is blocked in the Claude Code cloud sandbox; the scripts fall back to the local Chromium headless shell automatically.
- On Windows, run the scripts with `py` (or `python`) where the docs say `python3`: Windows' own `python3` is only a Microsoft Store shortcut. The Studio finds Python itself (`PYTHON` env var, `py -3`, `python`). Rendering a project with footage needs Windows Developer Mode (Remotion re-creates the footage link in `public/` as a symbolic link each time it bundles); `edit_init.py` says so when it is off.
